Aspect-based sentiment analysis

One review, many sentiments. Score the aspect, not the whole text.

AspectSense predicts whether a given aspect term in a review is Positive, Negative, or Neutral. A single review-level score fails when 2,330 of 4,373 unique reviews mix sentiments across aspects.

Fine-tuned microsoft/deberta-v3-base on 8,000 train rows. Official metric: Macro F1. Secondary: accuracy.

How it works

Pair the aspect with the review, then fine-tune a 3-class head

  1. Explore

    Inspect label balance on 8,000 train rows: Neutral 3,603, Positive 2,431, Negative 1,966. 4,373 unique reviews; 2,330 contain aspects with different sentiments.

  2. Clean a data trap

    The aspect term "nan" was read as missing. Fixed with keep_default_na=False.

  3. Map labels

    Negative 0, Neutral 1, Positive 2.

  4. Encode a pair

    Input as [CLS] aspect [SEP] review [SEP], truncating only the review, max length 128, dynamic padding.

  5. Fine-tune

    microsoft/deberta-v3-base with a new 3-class head. Weighted cross-entropy with inverse class frequency weights: Negative 1.357, Neutral 0.740, Positive 1.097.

  6. Select and submit

    Best checkpoint by Macro F1. Predict 2,000 test rows, write submission.csv, run the organizers’ validator. No API keys and no external inference API.

Problems fixed in training

  • warmup_ratio was rejected by the newer Transformers version, so warmup_steps=180 was used.
  • tokenizer= was renamed, so processing_class= was used.
  • FP16 unscale error, fixed with model = model.float().

Limitations

This page presents results. It does not run the model.

  • Neutral is the hard boundary

    Most errors involve Neutral. Direct Positive/Negative flips are uncommon (18 of 800).

  • Not tried

    The context_with_aspect_tag variant, multiple seeds, cross-validation, ensembles, larger models.

  • Overfitting after epoch 1

    Validation loss rose from 0.516 to 0.708 by epoch 4. Selection used Macro F1, not loss.
